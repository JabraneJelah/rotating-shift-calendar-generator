# Implementation plans

Create a numbered Markdown plan for substantial features or cross-cutting changes. Plans make scope and durable choices reviewable before code grows around them.

Use the next sequence number and a short kebab-case name, for example `002-schedule-generator-core.md`. Each plan should include context, goals, non-goals, affected boundaries, implementation steps, testing, documentation changes, risks/open decisions, and a status checklist. Update the plan as implementation reveals new facts; do not use it as a changelog for trivial edits.

Completed plans remain in this directory as decision context. If a plan is replaced, link to its successor and mark it superseded rather than deleting it.
